# Self-Contained Lattice Fröhlich Current-Correlation Design

## Goal

Add a self-contained two-stage example that computes the unsymmetrized
particle-current correlation of the periodic lattice Fröhlich model with
long-range diagonal electron-phonon coupling using HEOM-TT.

The example first equilibrates and checkpoints the Fröhlich HEOM-TT state,
then reloads that state and evaluates

\[
C_{JJ}(t)=\operatorname{Tr}\left[J e^{\mathcal{L}t}
\left(J\rho_{\mathrm{eq}}\right)\right].
\]

## Scope

Create `examples/lattice_frohlich_current_correlation` and focused package
tests. The directory owns all of its source and configuration. It does not
include or depend on source files from `examples/lattice_frohlich`,
`examples/holstein`, or `examples/holstein_current_correlation`.

The TTDynamics package API is not expanded for this example. Generated
outputs and Manifests are not committed.

## Directory Structure

The new directory contains:

- `Project.toml`: the standalone example environment;
- `README.md`: setup, equilibration, and correlation commands;
- `config.jl`: `LatticeFrohlichCurrentCorrelationConfig`, defaults, and
  validation;
- `model.jl`: periodic electronic Hamiltonian, normalized Fröhlich kernel,
  diagonal coupling operators, Brownian TPSD decomposition, and HEOM-TT
  problem construction;
- `utils.jl`: fixed-step propagation, measurements, particle-current
  operators, checkpoint metadata and validation, atomic file publication,
  CSV writers, and progress formatting;
- `equilibrate.jl`: fixed-time equilibration orchestration and checkpoint
  publication;
- `current_correlation.jl`: checkpoint reload, validation, current-source
  propagation, and result publication;
- `plotting.jl`: equilibration-population, current-correlation, and TT-rank
  plots.

The runtime-created `output/` directory is ignored by Git.

## Fröhlich Model

The single-excitation electronic Hamiltonian is the periodic nearest-neighbor
matrix

\[
H_{n,n}=\epsilon_n,\qquad
H_{n,n+1}=H_{n+1,n}=-J,
\]

including the periodic bond between the last and first site for more than two
sites.

The distance between bath site \(m\) and electronic site \(n\) is

\[
d(m,n)=\min(|m-n|,N-|m-n|).
\]

The default raw Fröhlich kernel is

\[
f(d)=(d^2+1)^{-3/2}.
\]

For every electronic site, the bath-site weights are normalized to unit
squared norm. Bath \(m\) couples through the diagonal Hermitian operator

\[
V_m=\sum_n w_{mn}|n\rangle\langle n|.
\]

Model construction verifies finite and nonnegative raw values, unit column
norm, symmetry, circulant translation symmetry, diagonality, Hermiticity, and
cyclic translation of the coupling operators.

Each coupling operator receives the same finite-temperature Brownian TPSD
expansion. The HEOM-TT system uses canonical
`[ket, bra, hierarchy...]` dimensions and the configured local hierarchy
size.

## Particle Current

Because the Fröhlich interaction is diagonal in electronic site occupation,
the particle-current operator is generated by the periodic hopping term:

\[
J=i J_0\sum_n\left(|n+1\rangle\langle n|
-|n\rangle\langle n+1|\right),
\]

where `J₀ = hopping_cm * icm2ifs` and the sum includes the periodic boundary
bond. The implementation verifies Hermiticity and embeds this operator both
as a ket-side HEOM-TT action and as a root-space observable.

The diagonal electron-phonon coupling affects the equilibrium state and the
Liouvillian propagation, but does not add a separate term to this particle
current.

## Stage 1: Equilibration

`equilibrate.jl`:

1. validates the local configuration;
2. decomposes the Brownian bath;
3. builds the lattice Fröhlich HEOM-TT problem;
4. propagates a localized electronic state for `1000.0 fs` by default;
5. reports step, physical time, trace, maximum and mean TT rank, and elapsed
   time at step zero, every `progress_interval`, and the final step;
6. trace-normalizes the final hierarchy state;
7. publishes diagnostics and the checkpoint.

The default outputs are:

- `output/lattice_frohlich_equilibrium.ttbin`;
- `output/lattice_frohlich_equilibrium_metadata.toml`;
- `output/lattice_frohlich_equilibration.csv`;
- `output/lattice_frohlich_equilibration_populations.png`.

## Checkpoint Metadata

Metadata is TOML-safe and uses:

- identifier `TTDynamics.LatticeFrohlichEquilibrium`;
- metadata version `1`;
- HEOM representation `twin-space-v1`.

It stores all configuration fields, equilibration time, complex TPSD data as
parallel real and imaginary arrays, hierarchy sizes, TT dimensions, and the
complete normalized Fröhlich weight matrix in a TOML-compatible nested real
array.

Reload validation rejects mismatches in:

- identifier, metadata version, or HEOM representation;
- physical or numerical configuration;
- TPSD exponents or coefficients;
- normalized Fröhlich weights;
- hierarchy sizes or TT dimensions;
- loaded state dimensions.

A checkpoint from the Holstein current-correlation example is therefore not
accepted accidentally.

## Stage 2: Current Correlation

`current_correlation.jl`:

1. requires both the equilibrium binary and metadata files;
2. reconstructs the same Fröhlich problem;
3. reloads and validates the equilibrium state;
4. constructs the periodic particle-current action and observable;
5. forms the unrounded source `J * rho_eq`, then applies the configured TT
   rounding for propagation;
6. propagates for `200.0 fs` by default;
7. reports physical time, maximum and mean TT rank, and elapsed time at the
   configured interval;
8. publishes the current correlation and rank diagnostics.

The default outputs are:

- `output/lattice_frohlich_current_correlation.csv`;
- `output/lattice_frohlich_current_correlation.png`;
- `output/lattice_frohlich_current_correlation_ranks.png`.

The CSV contains time, real and imaginary correlation components, maximum TT
rank, and mean TT rank. The exact unrounded source is used for the `t=0`
correlation value.

## File Safety

Both stages preserve the existing example semantics:

- `overwrite=false` rejects every conflicting target before replacing it;
- binary, metadata, CSV, and PNG files are staged before publication;
- a failed non-overwrite publication removes every newly published output;
- tests write only inside temporary directories;
- including either executable defines functions and constants but does not
  propagate, create directories, or write files.

## Testing

Focused tests cover:

- all configuration defaults and invalid values;
- periodic distances for odd, even, and two-site lattices;
- kernel normalization, symmetry, circulant structure, and invalid kernels;
- diagonal Hermitian coupling operators and cyclic translation;
- periodic Hamiltonian and particle-current matrix elements;
- current Hermiticity and HEOM-TT action/observable dimensions;
- Brownian bath and short HEOM-TT construction baselines;
- initial root trace and TT dimensions;
- short deterministic equilibration and current-correlation propagation;
- progress callback intervals and formatted output;
- metadata round trips and rejection of configuration, TPSD, kernel, and
  dimension mismatches;
- binary, TOML, CSV, and PNG overwrite and rollback behavior;
- exact output basenames and CSV schemas;
- isolated subprocess inclusion of both executables without output side
  effects;
- absence of cross-example includes.

## Completion Criteria

The feature is complete when the new directory runs the two stages without
source dependencies on other examples, the Fröhlich model and particle-current
contracts are characterized, checkpoints cannot be confused with Holstein
checkpoints, focused tests pass, and no broader-suite failure is caused by the
new example.
